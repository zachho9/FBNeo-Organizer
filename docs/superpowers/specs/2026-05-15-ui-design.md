# FBNeo Organizer — GUI Design Spec

**Date:** 2026-05-15
**Status:** Approved

## Overview

Add a PyWebView-based graphical user interface to the FBNeo Organizer, replacing the CLI entry point. The app is packaged as a single portable Windows `.exe` via PyInstaller, built automatically by GitHub Actions on each tagged release. No installer required — users download and double-click.

---

## Section 1: Architecture

**What changes, what stays:**

`organizer.py` retains all existing pure functions (`extract_platforms`, `parse_platforms`, `parse_allowlist`, `organize`, `run_listxml`, `find_exe`, `load_config`, `save_config`, `load_allowlist`). The `main()` function is removed — it is replaced by the GUI. A new `app.py` becomes the entry point.

**File structure:**
```
FBNeo-Organizer/
├── organizer.py          (backend logic, main() removed)
├── app.py                (PyWebView entry point + Python API class)
├── web/
│   ├── index.html        (single-page app shell)
│   ├── style.css
│   └── app.js
├── pyproject.toml        (add pywebview dependency)
├── config.toml           (auto-generated, git-ignored)
├── allowlist.txt         (user's list, git-ignored)
└── .github/
    └── workflows/
        └── build.yml
```

**How PyWebView works:** `app.py` opens a native window rendering `web/index.html`. A Python class (`Api`) exposes methods that JavaScript calls via `window.pywebview.api`. No HTTP server, no REST API — direct Python ↔ JS bridge.

## Section 2: UI Screens & Navigation

**Startup behaviour:**
- No `config.toml` → open on Settings tab, prompt user to set FBNeo directory
- Config exists → open on Platforms tab

**Sidebar (always visible):**
- Navigation: `Platforms` | `Allowlist` | `Settings`
- Dry run toggle (checkbox)
- Run button — the active tab determines the mode. Disabled when: Settings tab is active, no valid config, no platforms selected (Platforms tab), or allowlist empty (Allowlist tab)

**Platforms tab:**
- On load: calls `-listxml` once, caches result for the session; shows spinner during load
- Scrollable checklist of all platforms with game counts, sorted alphabetically
- Matches current CLI platform list behaviour

**Allowlist tab — two inner tabs:**

*Browse games:*
- Searchable list of parent games only (games without a `cloneof` attribute) loaded from the same `-listxml` cache (full title + short name)
- Clones are never shown — adding a parent automatically includes all its clones at run time (existing `parse_allowlist` behaviour)
- Click `+` to add to allowlist; already-added games show `✓`

*My list:*
- Current allowlist entries with `✕` to remove
- Changes auto-save to `allowlist.txt` immediately

**Settings tab:**
- FBNeo directory text input + Browse button (native Windows folder picker)
- Validates that `fbneo64d.exe` or `fbneo64.exe` exists on path change
- Shows derived paths (ROM dir, gone dir) once valid

**Results panel:**
- After clicking Run, replaces the main content area
- Shows a progress indicator while files are being moved
- Displays final summary: kept/moved counts by platform, warnings (unmatched names, skipped duplicates, move errors)
- "Back" button returns to the previous tab

## Section 3: Python ↔ JS API Bridge

`app.py` exposes an `Api` class to JavaScript via `window.pywebview.api`:

| Method | What it does |
|---|---|
| `get_config()` | Returns `{fbneo_dir, valid}` from current config |
| `browse_folder()` | Opens native Windows folder picker, returns selected path |
| `set_fbneo_dir(path)` | Validates path, saves `config.toml`, returns `{ok, error}` |
| `get_platforms()` | Runs `-listxml`, caches XML, returns `[{name, count}]` |
| `get_games()` | Returns `[{name, title}]` for parent games only (no clones) from the same `-listxml` cache |
| `get_allowlist()` | Reads `allowlist.txt`, returns list of short names |
| `save_allowlist(names)` | Writes `allowlist.txt` |
| `run(mode, selected, dry_run)` | Runs organizer (`mode` = `"platforms"` or `"allowlist"`). `selected` is a list of platform category names used only in platforms mode; ignored in allowlist mode (reads `allowlist.txt` directly). Returns `{counts, warnings}` |

`get_platforms()` and `get_games()` share one `-listxml` call — XML is parsed once and cached in memory for the session. Switching between tabs does not re-run the executable.

## Section 4: GitHub Actions Build

Triggers on version tags (e.g. `v1.0.0`). Produces a portable `FBNeo-Organizer.exe` attached to the GitHub Release.

```yaml
name: Build
on:
  push:
    tags: ['v*']

jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v3
      - run: uv sync
      - run: uv run pyinstaller FBNeo-Organizer.spec
      - uses: softprops/action-gh-release@v2
        with:
          files: dist/FBNeo-Organizer.exe
```

**Notes:**
- A `.spec` file is used instead of a CLI one-liner to bundle `web/` assets and declare PyWebView hidden imports
- `--onefile --windowed` flags are set in the `.spec` file
- `--onefile` adds ~2–3 seconds startup delay (temp extraction); acceptable for a desktop tool
- `pyinstaller` added as a dev dependency in `pyproject.toml`

**Release flow:**
1. Push a tag: `git tag v1.0.0 && git push --tags`
2. GitHub Actions builds `.exe` on Windows runner
3. `.exe` attached to GitHub Release automatically
4. Users download `FBNeo-Organizer.exe` from the Releases page

## Section 5: Error Handling

| Condition | Behaviour |
|---|---|
| No `config.toml` on launch | Open on Settings tab, prompt to set FBNeo directory |
| FBNeo path invalid (no exe found) | Red error message below path input in Settings tab |
| `-listxml` fails or times out | Error message in Platforms/Allowlist tab, Run button stays disabled |
| `-listxml` running | Spinner shown in Platforms tab and Browse games tab while loading |
| No platforms selected | Run button disabled |
| Allowlist empty in allowlist mode | Run button disabled |
| Game name in allowlist not in FBNeo database | Warning shown in results panel per unmatched name |
| File move fails (locked/permissions) | Per-file warning in results panel, operation continues |
| Duplicate already in `gone\` | Count of skipped duplicates shown in results panel |
| Run in progress | Progress indicator shown; Run button disabled until complete |

**Principle:** nothing destructive happens until the user clicks Run. All validation happens upfront and blocks the Run button.
